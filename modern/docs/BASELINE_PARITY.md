## Machine-testable invariants

1. Catalogue queries preserve source rows, image URLs, category names/slugs, colour, prices, original prices, flags and sort tie-breaks.
2. Browser-supplied prices/totals cannot affect cart/order persistence.
3. Cart mutation requires session + CSRF; max quantity 99; variant key keeps size/colour separate.
4. Checkout validates exact source limits/messages; order and snapshot rows commit atomically; cart clears only after commit; result is `ORDER_PLACED`.
5. Modern checkout and workflow writes use InnoDB transactions on one mysql2 connection; no network I/O occurs inside those transactions.
6. Guest order access requires number + code; DB stores only hash; session scoped; fresh ID after recovery; code reveal once.
7. Staff APIs require staff session; only permitted state edges accepted.
8. Review requires order owner, `READY_FOR_REVIEW`, exact revision, valid decision; history append and status changes are atomic.
9. Mock-up preview resolves to an allowlisted repository-local product image; no traversal or arbitrary remote URL.
10. Local email disabled by default, local allowlist only, loopback transport only, never customer address; email cannot gate checkout success.
11. No card fields, real payment integration, external email sender, or claim of payment processing.
12. SPA works with JavaScript enabled; no-JavaScript rendering is intentionally out of scope.
